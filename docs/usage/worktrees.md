# 仓库与 worktree

把仓库登记到 WebMux 后，可以为每个任务新建独立的 Git worktree，让多个 agent 并行工作而互不干扰；任务结束后删除 worktree，或释放空间但保留聊天记录，之后需要时再重建。

最快路径：

1. 点侧栏底部的「添加仓库」，填写服务器上已有仓库的路径。
2. 在侧栏仓库行点「⋯」选「新建工作树…」（也可在新建会话弹窗的位置里选「新建工作树…」），填写分支名并确认。
3. 在新工作树里新建会话，或在 [聊天模式](chat.md) 的快速开始页直接发任务：默认新建 worktree，也可切到「已有工作树」选择刚创建的工作树。

需要系统安装 Git；没有 Git 时终端功能不受影响。

> [!WARNING]
> 添加的仓库必须可信：Git 会按仓库配置执行 hooks 和 filters。

## 登记仓库

- **添加仓库**只登记已有仓库，不会 clone 或 init。登记信息在服务重启后保留。
- **从列表移除仓库**只移除登记，不删除目录或分支。
- **关闭会话**不会删除工作树。

## 新建工作树

在侧栏仓库行点「⋯」，选「新建工作树…」。默认只创建工作树，可创建新分支或检出未被占用的本地分支。

- **位置**：默认在仓库旁的 `<仓库名>.worktrees/<分支名末段>`。
- **不会**复制 `.env` 或安装依赖。
- **创建后启动会话**：勾选后才显示命令并启动；不勾选时不要求启动配置。
- 同一工作树可新建多个会话，它们**共享同一份文件**。

### 选择起点

创建新分支时选择“起始分支”（可搜索列表，按最近提交时间从新到旧列出本地分支与远程分支，如 `origin/*`），默认是主工作区当前本地分支。

- 选择本地分支后异步 fetch 其已配置上游。仅当本地尖端是上游提交的祖先时，默认使用上游最新提交的精确 OID；本地领先或分叉时保留本地提交；无上游或刷新失败时也保留本地基线。
- 选择远程分支后异步 fetch 对应远程，并以该远程分支的最新提交作为默认基线；刷新成功后也会同步更新可选的远程分支列表。
- 使用已有分支时不自动 fetch，也不会改用其上游提交。

“起始提交”下拉框列出所选分支最近 50 条提交（超出上限的起始提交仍会列出），无需输入提交 ID：

- 每行先显示提交标题，下方是短哈希、“本地最新”/“远程最新”标记和相对时间。
- 点「刷新上游」会 fetch 并把上游最新提交合并进列表；默认仍保留本地提交时，也可直接选择远程最新。
- 刷新动画不阻塞字段编辑或创建；刷新期间确认创建会使用当前可见基线。
- 切换分支或手动选择其他提交后，晚到响应不会覆盖较新的选择。

## 查看仓库面板

在侧栏仓库行点「⋯」选「仓库详情…」，打开仓库面板（窄屏为底部抽屉）。面板分四个分区：

| 分区   | 内容                                                                                                                     |
| ------ | ------------------------------------------------------------------------------------------------------------------------ |
| 概览   | 路径、Git 公共目录、默认分支、主页/总工作树数、远程数、上次获取远程时间、会话统计、读取时间                              |
| 工作树 | 全部工作树的上游同步状态、修改统计与最近提交；点击行查看工作树详情，「批量清理」进入批量删除                             |
| 分支   | 本地分支的上游、领先/落后与占用它的工作树；远程跟踪分支在单独的折叠组；可按名称搜索；未被占用的分支可「在新工作树打开…」 |
| 远程   | 每个远程的 fetch/push URL（凭据已脱敏，可复制）                                                                          |

- 同步状态全部在本机计算，不访问网络：领先/落后以本地远程跟踪引用为准，旁边标出上次获取远程的近似时间（从未获取显示“未知”）。
- 没有上游显示“无上游”，上游分支已被删除显示“上游已删除”，差距过大跳过计算时显示“未计算”，状态读取失败显示“未知”；这些情况都不会显示成 0/0。
- 工作树处于未完成的合并、变基、拣选、还原或二分时，详情与面板行会标出（如“正在变基”）。
- 远程 URL 中的密码或令牌显示为 `***`：`https://user:token@…` 只隐藏密码，`https://token@…` 隐藏整个用户名，SSH 地址原样显示。
- 面板内打开的工作树详情是同一抽屉里的子视图，点「返回」回到原分区，筛选与滚动位置不变。首页工作树分组的详情按钮和侧栏工作树行「⋯」菜单的「工作树详情…」打开同一份详情。
- 「在新工作树打开…」打开新建工作树弹窗（先关闭面板）：本地分支以“使用已有分支”选中它；远程分支以“创建新分支”把它作为起始分支，新分支名默认为去掉远程名的短名（`origin/fix/b` → `fix/b`）。确认后才创建。

## 切换工作树的分支

在首页工作树分组、侧栏工作树行或仓库面板工作树行的「⋯」菜单选「切换分支…」（面板的工作树详情里也有同名按钮），把这个工作树（含主工作区）原地切换到另一个分支或提交。bare、不可用或待清理的工作树没有这一项。

| 模式       | 目标                                                                 |
| ---------- | -------------------------------------------------------------------- |
| 已有分支   | 本地分支，或远程分支（新建同名本地分支并以它为上游）                 |
| 新建分支   | 输入名称（默认给出建议名，可「换一个」），从所选起点新建，不设置上游 |
| 分离到提交 | 当前提交的最近历史中的一个提交                                       |

- 每次选择都会先预览：当前 → 目标、阻止原因与警告。当前分支、已被其他工作树检出的分支，以及本地已有同名分支的远程分支，在列表中标出原因后不可选。
- **阻止切换**：未提交的已跟踪修改、进行中的合并或变基等、目标已被其他工作树检出、目标与当前相同。不会自动贮藏或丢弃修改。
  - 因修改受阻时可点绿色的「改为在新工作树打开」，用同一目标新建工作树，原工作树不受影响；
  - 目标被占用时点「转到该工作树」查看占用它的工作树。
- **运行中的会话**不会被关闭或重启，切换后直接看到新分支的文件；预览列出这些会话，须勾选「我已了解」才能切换。不想影响它们时同样可以改为在新工作树打开。
- 未跟踪文件不阻止切换，但目标分支跟踪了同名文件时切换失败并列出这些路径，工作树保持原样。
- 确认 5 分钟内有效；预览后出现新会话或分支前进时，切换被拒并自动重新预览。关闭页面不会中断进行中的切换。
- 切换后工作树 ID 与主页显示不变，标题改为新分支；已打开的代码视图约 5 秒内把变化的标签页标为“内容已更新”。

### 获取远程

面板标题栏的「获取远程」（窄屏只显示云朵下载图标）对仓库的全部远程执行 `git fetch --prune`，在任何分区都可以点：

- 进行中按钮显示“正在获取…”并禁用，不会重复请求；关闭面板不会中断获取。结束后标题栏下方逐个列出每个远程的结果（如“origin：已获取”），直到关闭面板或再次获取。
- 单个远程失败（认证失败、网络不可达、超时、远端拒绝）不影响其他远程；错误信息中的令牌显示为 `***`。
- 获取不会弹出密码或主机指纹提示：需要认证时直接报认证失败，请先在终端完成认证或确认主机指纹，再重试。
- 完成后面板与侧栏的领先/落后、上次获取时间随即更新；远端已删除的分支显示“上游已删除”。仓库没有远程时按钮禁用。

## 快进、推送与清理分支

面板显示出的同步状态可以直接处理。入口是工作树的「⋯」菜单（首页、侧栏与面板工作树行相同）、工作树详情的“分支与上游”一节，以及“分支”分区每个本地分支的「⋯」菜单：

| 分支状态                   | 提供的操作                         |
| -------------------------- | ---------------------------------- |
| 有上游，落后且不领先       | 快进到上游                         |
| 有上游，领先且不落后       | 推送…                              |
| 没有上游，或上游已删除     | 发布分支…                          |
| 领先与落后都有（已分叉）   | 不提供，说明需要在终端合并或变基   |
| 领先/落后未计算            | 快进与推送都显示，预览给出准确结果 |
| 未被任何工作树检出（分区） | 另有删除分支…                      |

- 每个操作先预览再确认，预览列出提交（最多 20 条加总数）、阻止原因与警告；确认前状态变了会自动重新预览。从面板发起时在面板内打开，点「返回」回到原处；从首页或侧栏发起时是单独的对话框。
- **快进**只用上次获取远程得到的远程跟踪分支，不联网；需要最新上游时先「获取远程」。检出该分支的工作树有未提交修改或进行中的合并、变基时不能快进；工作树下有运行中的会话时需勾选确认，会话不会被关闭。
- **推送**推送预览中的那个提交，不强制推送、不推送标签，会运行 `pre-push` 钩子。推送地址以脱敏后的形式显示。**发布**可以选择远程并修改远端分支名，成功后设为本地分支的上游。远端已有新提交时推送被拒绝，提示先获取远程再快进。
- **删除**只删本地分支，不删远端分支。预览分两组：“已包含”的提交都能从其他分支、远程跟踪分支、标签或工作树到达，默认勾选；“有独有提交”的分支（例如 squash 合并后的分支）列出这些提交，默认不勾选，需逐个勾选。被检出的分支不能删除。
- 删除结果逐项列出；已删除的行可复制恢复命令 `git branch <名称> <OID>`，在 Git 垃圾回收清除这些提交之前有效（默认约两周）。
- “分支”分区标明已合入默认分支的分支。未被检出、且上游已删除或已合入默认分支的分支是清理候选，标题行的「清理分支（N）」一次预览它们（单次最多 50 个），例如删除工作树后遗留的分支。

## 清理工作树：三种方式怎么选

| 方式         | 入口                                      | 目录 | 分支 | 已归档聊天               | 前提                                   |
| ------------ | ----------------------------------------- | ---- | ---- | ------------------------ | -------------------------------------- |
| **释放空间** | 已归档聊天的“⋯”菜单「释放空间」           | 删除 | 保留 | 保留，标为已释放，可重建 | 没有未提交修改、未跟踪文件或运行中会话 |
| **安全删除** | 侧栏工作树行「⋯」菜单的「删除 worktree…」 | 删除 | 保留 | 保留，标为已释放，可重建 | 没有未提交修改、未跟踪文件或活动会话   |
| **强制删除** | 安全删除被阻止时，在预览中勾选确认        | 删除 | 保留 | 保留，标为已释放，可重建 | 勾选关闭列出的会话并确认丢弃全部内容   |

三种方式都**只保留提交**：未提交修改、未跟踪文件与忽略文件（如 `.env`、`node_modules`）随目录永久删除，重建也找不回。

> [!CAUTION]
> 强制删除会关闭列出的会话，并永久丢弃目录中的全部内容（包括 `.env` 和未提交修改）。

### 释放空间

任务结束后想回收磁盘、又想保留聊天以便之后继续时用它。

1. 在侧栏聊天历史或首页“已归档”区，打开已归档聊天的“⋯”菜单，选「释放空间」。
2. 预览列出阻止原因、将保留的已归档记录、保存的提交与推送检查结果；确认。
3. worktree 目录被删除，该工作树下的全部已归档记录标为已释放（侧栏显示空心三角形）。

- 只对位于可用 linked worktree、尚未释放的记录提供；主工作区、直接目录、worktree 已不存在的记录不提供。
- 释放以工作树为单位，作用于其中全部已归档记录。
- 阻止释放：未提交修改、未跟踪文件、运行中会话、锁定、子模块或嵌套仓库。没有强制模式。
- 忽略文件不阻止释放，预览不逐项列出，只警告它们随目录永久删除。
- 提交由私有引用 `refs/webmux/released/<id>` 保住；记录保存原路径、提交与分支，服务重启后仍在。
- 确认后目标发生变化时拒绝并要求重新预览；删除失败时撤销标记与引用。

### 删除 worktree

在工作树菜单（或新建会话对话框位置列表中 linked 工作树旁的删除按钮）选「删除」，先看预览再确认。

- **安全删除**拒绝存在未提交修改、未跟踪文件或活动会话的工作树。忽略文件只在预览中警告（删除后丢失），不阻止删除。未锁定且目录已缺失的 `prunable` 登记也可安全清理，且不影响未选中的其他工作树。
- 主工作区、bare、locked 及含子模块的工作树不能通过页面删除。
- 预览列出该目录下已归档（已关闭或已中断）的混合会话。删除成功后，这些记录（强制删除时关闭的会话留下的也一样）保留并标为已释放，出现在仓库的“已不可用工作区”。
- 预览确认有时效；目标、会话或 HEAD 提交变化后需重新预览。
- HEAD 无法解析（例如还没有提交）时无法保存提交：不阻止删除，记录保持原样，只能查看或手动删除，不能重建。
- 删除成功后，若它是新建会话对话框的当前选择，则回退到主工作区。

### 批量管理与清理

当仓库累积了多份工作树（包括取消勾选“主页显示”后隐藏的空闲工作树），可从侧栏仓库行「⋯」菜单的「管理工作树…」或「主页显示…」底部的「批量管理…」打开仓库面板的“工作树”分区，选「批量清理」一次查看并清理：

- 分区列出该仓库全部工作树，支持搜索、按「全部 / 可安全清理 / 有阻塞 / 受保护」筛选，以及「选中全部可安全清理」（单次最多 50 个）。预览或执行期间不能切换分区。
- 预览默认**只安全删除无阻塞项并跳过受阻项**；仅当显式勾选强制删除授权后，才会关闭受阻项列出的活动会话并强制删除受阻目录。
- 本地分支始终保留，之后可在“分支”分区用「清理分支（N）」删除（见[快进、推送与清理分支](#快进推送与清理分支)）；可解析提交的已归档聊天同样转为已释放。单项状态变化或失败不会中断其余项，失败项会保留勾选以便重新预览重试。
- 外部删除了工作树目录后，分区显示「清理失效登记（N）」：只预选未锁定、目录已缺失且没有运行中会话的登记，直接进入同一个批量预览，确认后移除登记并保留分支。已锁定的失效登记不计入，行内提示“已锁定，需在终端解锁后清理”；N 为 0 时不显示。

### 重建并恢复

点已释放的记录（侧栏或“已不可用工作区”），先确认在原路径重建 worktree，再恢复聊天：

- 分支尖端仍是保存的提交且未被占用时，检出该分支；否则以 detached 方式检出保存的提交，并说明原因。
- 原路径被占用或仓库不可用时不可确认。取消则不做任何改动。
- 重建后，同一次释放下的记录都回到普通已归档状态，私有引用被删除。
- 删除已释放的记录只删除记录；最后一条被删时同时删除私有引用。

### 推送检查

释放空间与删除的预览都会检查要保留的提交是否已推送。它只读本地远程跟踪引用，不联网、不 fetch：

| 结果       | 显示                                                                 |
| ---------- | -------------------------------------------------------------------- |
| 已推送     | 列出至多 5 个包含该提交的远程分支                                    |
| 未推送     | 警告：仓库本地丢失或被清理后将无法重建，请先推送；只警告，不阻止确认 |
| 未配置远程 | 不提示                                                               |
| 未知       | 没有提交，或检查失败、超时                                           |
