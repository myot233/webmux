# Spec Delta

## Purpose

让用户从当前会话的 Diff 中选择文件、单行或连续代码行范围，生成包含准确路径、行号及版本来源的位置引用，并快速插入同一个终端会话供 agent 使用。发送遵循现有终端输入语义，让用户自行补充要求和提交，避免错误会话、错误版本及自动回车。

## ADDED Requirements

### Requirement: 文件与连续行位置可选择

系统 SHALL 支持文件级、单行和同一文件同一比较侧的连续行范围选择；桌面支持点击行号与 Shift 扩选，触屏支持选择起点/终点。选择 SHALL 可见、可清除，并包含所属文件和比较侧。跨文件、跨侧或不可显示的行 SHALL NOT 静默拼成连续范围。

#### Scenario: 桌面扩选与手机范围选择

- **WHEN** 用户点击新侧第 12 行并 Shift 点击第 18 行，或在触屏先选择起点 12 再选择终点 18
- **THEN** 系统高亮 12–18 的同侧范围，展示文件、双方版本中的所选侧与范围，并提供发送与清除动作

#### Scenario: 只有文件信息

- **WHEN** 条目为二进制、冲突、超限文件、纯重命名或模式变化
- **THEN** 用户可以选择文件位置，无法选择系统未展示或没有行号的内容

### Requirement: 引用准确表达版本与路径

系统 SHALL 使用当前工作树下所选比较侧的绝对路径，生成文件、`path:line` 或 `path:start-end` 位置。旧侧 SHALL 标注“HEAD 旧版本”或“索引旧版本”，已暂存新侧 SHALL 标注“索引版本”；删除行 SHALL NOT 被描述为当前工作区行。特殊路径 SHALL 可逆转义，控制字符 SHALL NOT 原样进入终端。

#### Scenario: 当前工作区新增行

- **WHEN** 用户选择未暂存 diff 新侧 `src/main.go` 的 12–18 行
- **THEN** 引用包含当前工作树的绝对路径和 `:12-18`，行号来自工作区新侧，不使用 Git patch 行偏移或主工作区路径

#### Scenario: 删除或重命名的旧行

- **WHEN** 用户选择已暂存删除/重命名 diff 旧侧行
- **THEN** 引用使用旧路径和旧行号并标注 HEAD 旧版本，不宣称旧路径或旧行号存在于当前工作区

#### Scenario: 路径含空格、换行或终端控制字符

- **WHEN** Git 路径含空格、引号、换行、反斜杠或控制字符
- **THEN** 预览与插入使用同一可逆转义文本，不原样插入换行/控制序列，不将路径转换为 shell 命令；无法无损表示的路径禁用发送并显示原因

### Requirement: 发送通过当前终端输入且不自动提交

系统 SHALL 提供“发送位置到终端”动作，插入用户可见的位置引用到当前会话输入，遵循应用启用的粘贴模式，不追加回车、清空已有输入、发送控制键或自动调用第三方 agent API。动作 SHALL 使用明确的用户点击并在发送前检查当前连接与会话状态，不从等待启发式推定可以自动提交。

#### Scenario: 当前 agent 已有草稿输入

- **WHEN** 连接可用，用户选中代码位置并点击发送
- **THEN** 位置经终端粘贴路径插入当前输入光标处，已有内容保持；用户可继续补充文字并自行按回车，不发送给其他会话

#### Scenario: 普通 shell 会话

- **WHEN** 当前会话是 Shell 而非 agent 预设，用户点击发送
- **THEN** 按同样终端输入语义插入位置文本，不执行包装命令；按钮文案与说明不声称已调用 agent 或完成任务

### Requirement: 不可发送时保留选择并准确反馈

连接断开、恢复中、会话退出/不存在或终端尚未初始化时，发送 SHALL 被禁用或明确拒绝；失败 SHALL 保留选择，不缓存引用供重连后自动重发。不论本地发送结果如何，系统 SHALL NOT 声称 agent 已接收、阅读或处理位置；成功反馈仅表示已写入当前可用终端连接。

#### Scenario: 点击时连接刚好断开

- **WHEN** 用户点击发送时终端连接已不可用
- **THEN** 页面显示未发送并保留选择，重连不会补发，用户可在恢复后重新点击

#### Scenario: 点击后发生网络故障

- **WHEN** 位置已提交本地 WebSocket 发送，但随后连接中断
- **THEN** 系统不声称 agent 已确认接收或处理，不自动重试而造成重复输入

### Requirement: 移动端发送返回终端且保留会话

窄屏下发送成功 SHALL 切回“终端”标签并使终端恢复可见尺寸；失败 SHALL 留在 Diff 并保留选择。标签切换 SHALL NOT 重建终端、关闭 PTY 或改变会话 ID。发送 SHALL NOT 强制唤起手机软键盘；用户通过既有键盘按钮继续输入。

#### Scenario: 手机查看 diff 后发送

- **WHEN** 用户在 Diff 标签中发送一个有效位置且本地发送成功
- **THEN** 页面切回原终端，位置插入原会话，无额外回车；键盘未打开时不会因发送动作被强制打开

### Requirement: 刷新与会话变化使旧选择失效

刷新发现文件内容、比较来源或路径变化，切换文件/会话或工作树身份失效时，系统 SHALL 清除旧行选择。引用 SHALL 来自当前展示的 diff 快照；系统 SHALL 明示读取时间，不声称位置在外部持续写入下具有实时事务保证。

#### Scenario: 刷新后代码行移动

- **WHEN** 用户选中 12–18 行后刷新发现文件内容已变化
- **THEN** 旧选择清除，发送按钮不继续使用旧行号，用户必须在新 diff 中重新选择

#### Scenario: 从会话 A 导航到会话 B

- **WHEN** 用户在 A 选择位置后进入 B 的终端页
- **THEN** A 的文件选择、引用和未完成请求不进入 B，也不向 B 的 PTY 注入内容
